# 素材重命名与 API 上传操作手册

## 适用范围

用户要求执行以下任一操作时使用本手册：

- 盘点某一期或某个文件夹的素材；
- 将临时文件名改为中文描述名；
- 通过管理 API 批量上传、补传素材；
- 修改已上传素材的分类、类型或其他元数据；
- 验证线上素材记录、原图或缩略图。

这是内容运营操作，不是代码开发任务。除非用户另外明确要求，否则不得为此创建或切换 Git 分支、创建开发规格/计划、提交代码、部署应用或执行全量项目构建测试。

## 标准流程

### 1. 读取与盘点

1. 确认用户给出的一个或多个绝对目录。
2. 递归或非递归范围以用户描述为准；未说明时先按目录内直接文件处理。
3. 仅处理 `.png`、`.jpg`、`.jpeg`、`.webp` 图片。
4. 排除文档、脚本、布局 JSON、缓存和隐藏文件。
5. 统计每个目录的图片数、扩展名和文件大小。
6. 识别哈希名、时间戳名、`Pasted-*`、乱码名以及同名文件。

### 2. 本地重命名

只有用户明确要求修改本地原文件时才执行重命名；否则仅调整平台标题。

1. 需要看图才能命名时，先制作缩略图联系表并检查图片内容。
2. 默认使用“类型-视觉特征”格式，例如：
   - `星星-红色蜡笔.png`
   - `插画-粉色小鹿.jpg`
   - `背景-灰粉波点涂鸦.jpg`
3. 名称应简洁、可搜索、能区分颜色/内容/构图，禁止继续使用无意义序号或哈希。
4. 在修改前生成完整的“原名 → 新名”映射并检查：
   - 所有源文件存在；
   - 目标文件名唯一；
   - 目标路径尚不存在；
   - 扩展名保持不变。
5. 未经用户同意不得覆盖已有文件。
6. 重命名后重新统计文件数，并确认不存在遗漏、重复或残留临时名。

### 3. 分类与素材类型

平台 `category` 按内容用途判断：

- 独立贴纸、装饰元素、图标、角色、花朵或星星元素：默认 `贴纸`；
- 背景纸、纹理、满幅图案以及用户明确指定的背景目录：`背景`；
- 用户指定分类时，以用户指定为准。

平台 `materialType` 按素材形态判断：

- 单个独立元素：`single`；
- 白底、透明底、A6 排版、合集、合并素材、整版或满版：`bundle`。

创建记录时默认：

- `isPremium: true`
- `status: 1`
- `sortOrder: 0`
- `issueYear` 与 `issueNumber` 必须显式提交且成对出现，例如 `2026`、`7`；数据库以数值保存，界面显示为“2026年第七期”
- 描述包含年份、期数和来源文件夹；
- 标签包含期数、分类、来源主题以及“单个素材”或“合并素材”。

描述和标签中的期数只用于展示与搜索辅助；小程序期数筛选以 `issueYear`、`issueNumber` 为唯一依据。

### 4. 认证信息安全

1. 管理 API token 由用户提供。
2. token 只作为当前命令进程的临时环境变量使用。
3. 禁止将 token 写入脚本、配置文件、命名清单、上传报告、日志或 Git。
4. 命令结束后删除临时环境变量。
5. 不得通过读取生产 `.env`、反查密码哈希或绕过认证来获取凭据。
6. token 失效时停止上传并向用户索取新的 token。

### 5. API 上传顺序

生产 API 默认地址：`https://shouzhangku.store/api`。

1. 调用 `GET /api/v2/admin/materials` 获取现有记录并按标题精确查重。
2. 同一期、同一素材已经存在时跳过，不重复上传。
3. 不同素材发生同名时，平台标题添加期数或主题前缀，不覆盖旧记录。
4. 调用 `POST /api/v2/admin/upload` 上传图片，取得 `imageUrl` 和 `thumbnailUrl`。
5. 上传成功后调用 `POST /api/v2/admin/materials` 创建素材记录。
   请求体必须包含从来源目录确认的 `issueYear`、`issueNumber`，不得仅依赖描述或标签中的期数文本。
6. 不得删除或修改旧记录来解决重名，除非用户明确要求。
7. 单张失败不得阻断其他图片；将失败项写入报告后单独重试。
8. 重试前必须重新查重，避免已成功记录被重复创建。

### 6. 大文件处理

1. 遇到 HTTP 413 时，先确认文件大小和线上请求体限制。
2. 优先生成临时优化副本上传，不修改用户原图。
3. 临时副本必须保持原始像素尺寸和透明背景需求。
4. 优化后仍使用原文件标题、来源目录、分类和类型。
5. 未经用户授权不得修改生产 Nginx 配置或重启服务。

### 7. 分类调整

用户要求调整某个本地文件夹对应素材的分类时：

1. 读取该文件夹中的图片标题集合；
2. 从管理 API 获取素材列表；
3. 按标题精确匹配，确认匹配数量等于本地图片数量；
4. 仅通过 `PUT /api/v2/admin/materials/{id}` 更新用户指定字段；
5. 不改变标题、图片 URL、类型、状态或其他未指定字段；
6. 更新后再次从 API 回查全部目标记录。

## 上传后验证

不得仅依据上传进程输出宣布完成。必须独立验证：

1. 上传报告满足 `uploaded + skipped = 预期图片数`；
2. `failed = 0`，否则列出失败项并重试；
3. 管理 API 中能匹配全部预期标题；
4. 每条记录的 `category`、`materialType`、`status` 正确；
5. 每条有期数来源的记录，其 `issueYear`、`issueNumber` 与来源目录一致；
6. 每条记录都有 `imageUrl` 和 `thumbnailUrl`；
7. 对新增记录的原图与缩略图执行 HTTP 检查，全部返回 2xx；
8. 最终向用户报告各目录数量、新增/跳过/失败数量及报告路径。

## 历史期数识别

只读生成复核清单：

```powershell
$env:ADMIN_TOKEN='<临时管理令牌>'
node scripts/identify-material-issues.mjs
Remove-Item Env:ADMIN_TOKEN
```

脚本只读取管理 API 与 `release/*.json`，将识别结果写入 `release/material-issue-recognition-*.json`，不会调用更新接口。`high` 结果仍需人工复核，`conflict` 与 `unmatched` 不得自动回填。

检查长时间运行的上传任务时，应先确认进程状态和报告是否生成，不得因为终端暂时没有新输出就判断任务已中断，也不得在原进程仍运行时并发重跑。

## 报告规则

报告保存在项目 `release/` 下，建议命名：

```text
upload-<期数或主题>-materials-YYYYMMDD-HHMMSS.json
```

报告可以包含：来源目录、文件名、平台标题、记录 ID、分类、类型、上传/跳过/失败状态和错误信息。

报告禁止包含：token、密码、请求 Authorization 头、生产环境变量或其他凭据。
