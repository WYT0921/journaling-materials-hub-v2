# 第三期、第四期素材重命名与上传设计

## 目标

将 `E:\图片\手账素材\2026\第三期` 与 `E:\图片\手账素材\2026\第四期` 的图片通过管理 API 上传到平台。第四期的哈希名和 `Pasted-*` 临时文件直接在本地重命名为可读、唯一的中文文件名。

## 命名规则

- 第四期临时文件使用“类型-视觉特征”格式，例如 `星星-红色蜡笔.jpg`。
- 同一视觉主题通过颜色、构图或表现形式区分，所有目标文件名必须唯一。
- 第四期已有明确名称的 `星星-白底`、`星星-透明底`、`花-白底`、`花-透明底` 保持不变。
- 第三期现有 6 个文件名保持不变。
- 若平台已有同名但并非同一批素材，上传标题增加期数前缀消歧，例如 `第三期-粉色-白底`。

## 分类与类型

- 星星、花朵及第三期贴纸素材默认分类为 `贴纸`。
- 白底、透明底以及明显的整版合集图片使用 `materialType=bundle`。
- 独立元素图片使用 `materialType=single`。
- 标签包含期数、分类、主题以及单个/合并素材类型。

## 执行流程

1. 生成第四期原名到新名的完整映射，并检查目标名冲突。
2. 在同一目录内执行本地重命名，不改动图片内容。
3. 读取平台素材列表，按标题精确查重。
4. 对未上传项依次调用图片上传接口和素材创建接口。
5. 保存不包含认证信息的上传报告。
6. 从管理 API 回查新增记录，并逐一检查原图和缩略图 URL。

## 错误处理与验证

- 任一重命名目标已存在时停止，不覆盖文件。
- 单张上传失败不阻断其余图片，失败项进入报告并单独重试。
- 上传完成条件：本地图片数与“新增 + 已确认重复”总数一致；新记录分类、类型、图片 URL 完整；所有新图片 URL 可访问。
- API token 只作为当前进程环境变量使用，不写入文件或报告。
